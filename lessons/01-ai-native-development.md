# AI 보조 코딩에서 AI-Native 개발로

## 이번 강의의 질문

> Agent에게 기능을 요청하는 것과 Agent가 제대로 일할 환경을 설계하는 것은 무엇이 다를까?

1강에서 개발 과정에 AI가 들어오며 사람과 도구의 역할이 달라지고 있음을 살펴봤습니다. 2강에서는 그 변화를 실제 개발 업무의 관점에서 정리합니다.

## 세 단계로 보는 변화

### AI-assisted coding

사람이 문제를 이해하고 설계와 구현을 주도합니다. AI는 코드 조각 작성, 설명, 오류 해결 같은 일부 작업을 돕습니다.

### Agentic development

사람이 하나의 목표나 작업을 맡기면 Agent가 저장소를 살펴보고 여러 파일을 수정하거나 명령을 실행합니다. Agent는 코드 작성 도구를 넘어 일정한 범위의 개발 작업을 수행합니다.

### AI-Native development

개발자는 개별 코드를 직접 작성하는 일뿐 아니라 목표, 맥락, 도구, 권한 경계, 품질 기준을 설계합니다. Agent는 그 환경 안에서 탐색·구현·검증을 수행하고, 사람은 결과와 위험을 판단합니다.

```text
AI-assisted coding
사람이 개발을 주도하고 AI가 일부 작업을 보조
        ↓
Agentic development
사람이 작업을 맡기고 Agent가 여러 개발 단계를 수행
        ↓
AI-Native development
사람이 목표와 작업 환경을 설계하고 Agent가 검증 가능한 결과를 만듦
```

이 단계들은 서로를 완전히 대체하는 구분이라기보다, 개발 과정에서 AI에 맡기는 범위와 이를 둘러싼 설계가 넓어지는 흐름으로 이해하면 좋습니다.

## 개발자의 역할

AI-Native 방식에서 개발자는 다음 일을 더 의식적으로 수행합니다.

- 문제와 완료 조건을 구체화한다.
- 프로젝트가 이미 정한 구조와 규칙을 Agent가 찾을 수 있게 한다.
- Agent가 사용할 도구와 수정 범위를 정한다.
- 자동화된 테스트와 사람이 확인할 항목을 설계한다.
- 결과를 근거와 함께 검토하고 책임 있는 결정을 내린다.

이 변화는 “개발자가 더는 코드를 이해하지 않아도 된다”는 뜻이 아닙니다. 오히려 Agent의 변경이 목표와 시스템에 맞는지 판단하려면 코드와 제품 맥락을 이해해야 합니다.

## 강의의 관찰 관점

뒤이어 진행할 실습에서는 같은 기능을 조건을 달리해 요청합니다. 한 조건에서는 짧은 요청만 주고, 다른 조건에서는 명세·프로젝트 규칙·검증 방법을 제공합니다. 어느 쪽의 코드가 더 많은지를 보는 대신 다음을 관찰합니다.

- Agent가 어떤 결정을 스스로 추측했는가?
- 기존 구조와 제약을 지켰는가?
- 결과를 재현하고 확인할 근거가 있는가?
- 사람이 개입하거나 수정해야 한 지점은 어디인가?

## 기억할 문장

> AI-Native 개발자는 Agent에게 코드를 맡기는 데서 멈추지 않고, 올바른 결과를 만들고 확인할 수 있는 작업 환경을 설계한다.
