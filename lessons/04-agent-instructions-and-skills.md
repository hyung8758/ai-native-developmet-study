# AGENTS.md와 Skills

Agent가 프로젝트에서 일할 때는 작업 요청 외에도 지속 규칙과 반복 절차가 필요할 수 있습니다. `AGENTS.md`와 Skill은 비슷해 보이지만 쓰임이 다릅니다.

## AGENTS.md: 프로젝트의 지속 규칙

`AGENTS.md`에는 여러 작업에 걸쳐 계속 적용되는 프로젝트 지침을 둡니다.

- 프로젝트의 구조와 주요 기술
- 지켜야 할 아키텍처나 호환성 규칙
- 테스트와 실행 방법
- 변경을 마친 뒤 필요한 보고 방식

짧고 안정적인 규칙을 중심으로 작성하세요. 모든 작업의 세부 절차, 긴 배경 설명, 특정 이슈에만 해당하는 요구사항을 한 파일에 모으면 지침이 길어지고 유지하기 어려워집니다.

## Skill: 반복되는 업무 절차

Skill은 특정 유형의 업무를 수행하는 방법을 설명하는 재사용 가능한 작업 지침입니다. 예를 들어 웹 UI 변경 후 서버를 실행하고 주요 동작과 브라우저 오류를 확인하는 절차를 둘 수 있습니다.

Skill은 목적이 분명해야 합니다. “모든 개발을 잘하는 법”처럼 범위가 넓은 지침보다 “API 변경 뒤 회귀 테스트를 확인하는 절차”처럼 언제 쓰고 무엇을 산출하는지 명확한 지침이 유용합니다. 필요한 경우 체크리스트, 예제, 스크립트 같은 보조 자료를 함께 둘 수 있습니다.

## 차이와 연결

```text
AGENTS.md
  프로젝트 전반에서 지속적으로 지킬 규칙

Skill
  특정 업무를 수행할 때 재사용하는 절차와 참고 자료

작업 명세
  이번 작업에서 달성할 목표와 범위
```

`AGENTS.md`는 어떤 Skill이 있는지와 프로젝트의 공통 규칙을 알려줄 수 있습니다. Skill은 해당 업무에서 사용할 세부 절차를 담습니다. 작업 명세는 이번 요청의 요구사항을 정의합니다.

## 실습 저장소에서 둘 위치

이 과정에서는 강의 문서에 전역 규칙을 걸지 않습니다. 실험 앱 안에 Agent 설정을 둬야 설정이 없는 조건과 있는 조건을 비교할 수 있고, 강의 작성이나 다른 실습에 설정이 섞이지 않습니다.

```text
labs/
└── task-board/
    ├── starter/                 # 설정이 없는 기본 앱
    ├── harness/                 # 규칙과 Skill을 적용하는 실험용 앱
    │   ├── AGENTS.md
    │   └── .agents/
    │       └── skills/
    │           └── webapp-verification/
    │               └── SKILL.md
    └── README.md                # 실험 실행 방법
```

위 구조는 이후 실습 코드를 만들 때 적용할 제안입니다. 실제 Agent 도구에 따라 인식하는 지침 파일 이름과 Skill 검색 경로가 다를 수 있으므로, `labs/`를 구현할 때 사용할 도구의 공식 규칙에 맞춰 경로를 확정해야 합니다. 강의 저장소 최상위에는 실험 결과에 영향을 줄 수 있는 범용 `AGENTS.md`를 두지 않는 편이 좋습니다.

## 지침은 검증하고 다듬기

지침 파일을 만들었다고 Agent가 항상 의도대로 따르는 것은 아닙니다. 대표적인 작업으로 직접 사용해보고, 지나치게 길거나 중복되는 규칙을 제거하고, 실제로 놓친 항목만 보완합니다. Skill도 언제 유용하고 언제 불필요한지 살펴봐야 합니다.
