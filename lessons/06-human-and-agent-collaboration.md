# 사람의 역할과 Agent 협업

## 사람은 무엇을 맡는가

Agent가 구현과 반복 작업을 수행해도 사람은 목표와 품질에 대한 책임을 집니다. 사람은 제품 의도와 우선순위를 정하고, 중요한 제약을 명시하며, 변경 결과가 실제 사용자와 시스템에 미치는 영향을 판단합니다.

최종 검토에서는 Agent의 요약만 읽지 말고, 필요에 따라 테스트 결과와 diff를 확인합니다. 문제가 남았다면 무엇이 검증되지 않았는지 분명히 남겨야 합니다.

## 여러 Agent를 언제 쓰는가

작업을 나누면 유용한 경우가 있습니다. 예를 들어 구현과 독립적인 코드 리뷰를 분리하거나, 서로 독립된 하위 작업을 병렬로 수행할 수 있습니다.

다만 여러 Agent를 쓰면 조율 비용과 결과 충돌 가능성이 생깁니다. 하나의 작은 변경을 여러 역할로 쪼개면 전달과 통합에 시간이 더 들 수 있습니다. 먼저 단일 Agent가 처리하기 어려운 독립 작업인지, 각 역할의 입력과 결과를 명확히 나눌 수 있는지 판단합니다.

리뷰 Agent는 유용한 추가 관점을 줄 수 있지만, 테스트나 사람의 검토를 대신하는 보증 장치로 취급해서는 안 됩니다. 리뷰 결과도 구체적인 코드 위치와 재현 가능한 근거를 기준으로 살펴봅니다.

## Human gate

위험도에 비례해 사람이 직접 판단해야 하는 지점을 둡니다. 예를 들어 외부 API 변경, 데이터 삭제, 보안 민감 변경, 배포 결정은 자동화 결과만으로 승인하지 않고 사람이 diff와 검증 근거를 확인할 수 있습니다.

```text
명세 → 구현 → 테스트 → 독립 검토 → 사람의 판단 → 통합
```

사람의 검토는 Agent를 불신한다는 의미가 아니라, 책임과 맥락에 관한 결정을 적절한 주체가 맡는 과정입니다.

## 강의 마무리 질문

- Agent의 완료 보고 외에 어떤 근거를 확인했는가?
- 이번 작업에서 사람이 직접 판단해야 했던 부분은 무엇인가?
- 다음 실행에서 명세나 프로젝트 맥락을 어떻게 개선할 것인가?

## 핵심 정리

AI-Native 개발은 코드 생성량보다 작업을 설계하고 결과를 검증하는 능력에 달려 있습니다. 좋은 환경은 Agent가 추측할 부분을 줄이고, 실패를 발견하기 쉽게 하며, 사람이 결과를 책임 있게 판단할 수 있도록 돕습니다.
